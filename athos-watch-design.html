Product & Technical Design · Rev 1.0

Athos Apple Watch 全天候记忆采集，与可溯源的「数字分身」蒸馏系统

形态 watchOS + iOS + 云端 日期 2026-11-16 状态 待评审

这不是一个录音笔。录音笔的产出是文件；本产品的产出是结构化的自我——可被检索、可被质询、可被复述的长期记忆与决策模式。录音只是原料，蒸馏才是产品。

00结论先行：先纠正一个产品前提

Feasibility verdict

「Apple Watch 24×7 不间断录音」在该平台上不可实现，且不应作为产品承诺。三重硬约束叠加：

1）功耗。麦克风常开 + 音频 DSP 持续唤醒会阻止 SoC 进入深度休眠。参照现有手表扬声器/麦克风类应用实测区间，连续录音的整机功耗约 35%–45%/小时，满电可用时长约 2–2.5 小时。
2）系统。watchOS 不存在通用的后台音频采集权限。App 抬腕时在前台，垂腕后即被挂起；维持后台运行的合法路径只有 HKWorkoutSession、限定时长的 WKExtendedRuntimeSession（单次上限约 1 小时，且类型受限）、或音频播放后台模式。
3）审核。为「非健身用途」长期占用 HKWorkoutSession 或后台音频模式，属于 App Store 审核明确关注的模式滥用，存在高概率被拒风险。

可行的产品定义是：全天候待命（on-watch sensing）+ 事件驱动采集 + iPhone 作为主力采集面 + 充电窗口批量上传。手表的价值不在「录得久」，而在「随时在手、一键即达、可不看屏幕完成标记」。

这个纠正不是退让，而是把产品从「续航竞赛」拉回「价值密度竞赛」。下面所有设计都建立在这个前提上。

01产品定位与用户价值

1.1 一句话定义

一个把日常对话蒸馏成可溯源个人记忆，并逐步训练出能替你复述判断逻辑的分身的私人系统。手表是它的采集触角与遥控器，iPhone 是它的随身硬盘，云端是它的蒸馏厂。

1.2 三类刚需，按可验证性排序

需求用户真实动机为什么手表形态更优
不再遗忘会议里被口头交代的事、路上想到的点子、别人随口说的偏好，事后无法复原。手机常不在手边/不便掏出；抬腕一键即录，摩擦趋近于零。
不再重复解释同一套背景要向不同人、不同 AI 反复陈述，成本极高。长期采集是「个人上下文」的唯一来源，一次沉淀、处处复用。
校准自我认知我以为我这样决策，实际我那样决策。口头承诺与真实行为存在系统性偏差。被动采集避免了「事后美化」，是唯一诚实的行为数据源。

1.3 明确不做的事

  • 不做取证工具。不提供「录音为证」类功能与话术，从产品文案层面切断法律风险联想。
  • 不做隐形录音。采集状态必须可见（表盘常驻标识 + 指示灯 + 触觉脉冲）。
  • 不做无源生成。分身输出的每一句判断，必须能回跳到原始录音时间戳，否则不输出。

03系统架构

L0 采集
端侧多源采集面Apple Watch（触发、标记、短时会话采集）、iPhone（常驻收音主力）、AirPods（免手麦克风，通勤与行走场景）。三源不并行抢麦，由会话仲裁器按场景择一。
L1 边缘
加密缓冲与断点续传端侧 VAD 切段（静音 400ms 断句，单段上限 60s），Opus 16kbps 单声道编码（约 7.2MB/小时）。AES-GCM 加密，密钥存 Secure Enclave。本地环形缓冲区保留 72 小时，WiFi + 充电窗口批量上传，弱网自动降码率。
L2 转写
转写、说话人分离与时间对齐优先使用系统端侧长音频转写能力（低延迟、零边际成本、数据不出端）；置信度低的片段回退云端批量 ASR。输出带词级时间戳与说话人标签的转写稿，作为后续一切蒸馏的唯一事实底稿。
L3 蒸馏
三层压缩：事实 → 认知 → 人格每层有独立的 schema、独立的更新频率、独立的人工确认入口。层与层之间通过证据 ID 双向链接（详见 §05）。
L4 图谱
时序记忆图谱人物、组织、项目、事件、决定、承诺、观点为节点；参与、因果、矛盾、演化、归属为边。所有节点携带 occurred_at、recorded_at、source_span、confidence 四个元字段。
L5 分身
人格层与输出面风格模型（句长、语气、口头禅）、价值排序、决策启发式、禁忌清单。输出形态：日终回顾、周度复盘、会前简报、决策对照、可溯源问答。
架构取舍

把转写放在端侧、把蒸馏放在云端，是成本与隐私的最优切分：转写是高带宽、低智能的活（本地做省钱且不出端），蒸馏是低带宽、高智能的活（云端做效果更好且只传文本）。这条切分线同时把云成本压到可订阅的水平（见 §09）。

04采集策略与功耗预算

核心机制是分级唤醒：绝大多数时间系统处于极低占空比的声学感知，只有当检测到「有人说话且持续超过阈值」才升级到完整采集。

P0声学哨兵

仅运行能量 + 过零率的轻量 VAD，帧长 30ms，不落盘、不转写。判定「环境是否有可记录的人声」。

P1触发判定

人声持续 ≥ 3 秒且信噪比达标，或检测到唤醒词「记一下」，升级为完整编码并落盘。

P2完整采集

编码、切段、加密、写环形缓冲区。遇到静音 90 秒自动降回 P0。

P3人工标记

用户抬腕双击即打「重点」标记，生成 ±60 秒高优先级片段，进入当日回顾首屏。

运行模式采集占空比预估功耗适用判断
连续录音100%~35–45%/h不可作为产品形态使用
哨兵 + 触发采集15%–25%~8–12%/h手表独立时的推荐档，约 7–10 小时
纯待命 + 手动触发<5%~3–5%/h极端省电档，全天可用
iPhone 兜底—手表 ~3%/h推荐默认：手表只做控制面与标记

功耗为基于器件与现有同类应用实测的工程估算区间，需在 Series 9 / Ultra 2 两颗芯片上做实测校准后写入产品承诺，严禁直接把估算值用于对外宣传。

断点与失败设计

  • 缓冲区写满时按「低置信度段 → 无声段 → 最旧段」的优先序淘汰，绝不丢弃已标记重点。
  • 存储中断、麦克风被抢占、系统杀死进程，均写入 gap_event，在回顾界面明确显示「此处有 12 分钟未记录」，不假装完整。
  • 低电量模式（<20%）自动降为「仅手动触发」，并推送一次告知。

05三层蒸馏管线：从音频到人格

这是产品的真正壁垒所在。常见错误是「转写 + 摘要」——那只是压缩，不是蒸馏。蒸馏要求每一层的输出都是可被下一层消费的结构化断言，而不是自然语言段落。

5.1 第一层：事实层

目标是把流水对话还原为结构化事件。抽取字段固定为七元组：who / whom / when / where / what / decision / commitment。关键设计：

  • 只抽取有说话人归属的断言。无法确定谁说的一句话，标记为 unattributed，不进入事实库。
  • 承诺单独建模。「我周五给你」是一种带履约风险的断言，必须能从图谱里被查询、被提醒、被核销。
  • 每条事实附 source_span。指向转写稿的字符区间与音频时间戳，这是全部可溯源性的根。

5.2 第二层：认知层

从多条事实中归纳出稳定的判断倾向。产出物是「观点卡片」而非摘要：

{
  "claim":    "在信息不足时，我倾向先小成本试跑，而不是继续调研",
  "evidence": ["ev_20261103_1142", "ev_20261028_0930", "ev_20261015_1610"],
  "conditions": "决策可逆 且 试跑成本 < 2 人日",
  "counter":   ["ev_20261112_1005"],          // 反例，必须保留
  "confidence": 0.72,
  "updated_at": "2026-11-12T18:20:00+08:00"
}

三条硬规则：反例不得被平均掉（counter 字段强制保留）；条件必须显式（去掉条件的观点会退化成正确的废话）；置信度随证据数递减边际，避免同一件事在十次对话里重复出现就被误判为强信念。

5.3 第三层：人格层

人格层不是「模仿说话」，而是四类可评估的参数：

维度刻画什么怎么验证
表达风格句长分布、语气词频率、开场与收束习惯、术语偏好盲测：让同事分辨哪段是本人原话、哪段是分身生成
价值排序冲突时的取舍优先级（速度 vs 稳妥、关系 vs 正确）情境题：给出两难场景，比对分身选择与本人历史选择
决策启发式默认路径、否决条件、升级到人决策的触发线预测题：对已发生的决策做盲预测，算 Top-1 命中率
边界与禁忌不承诺的事、不参与的场合、不愿被记录的领域越界测试：主动诱导分身越界，检查拒绝率
最容易做错的地方

把「分身」做成「一个说话像我、但记忆靠猜的聊天机器人」。这类产品的失败点不是风格不像，而是记忆错误——一旦用户发现分身在编造他"说过"的话，信任一次性归零且不可恢复。所以人格层的输出必须默认携带「依据片段编号 + 置信度」，低置信时明说「我不确定，你上次类似情境是这么处理的」而不是给一个笃定答案。

06数据模型与记忆图谱

Person   { id, name, org, relation, first_seen, aliases[] }
Event    { id, occurred_at, duration, place, participants[], topic[] }
Fact     { id, event_id, speaker_id, type, payload, source_span, confidence }
Commit   { id, from, to, what, due_at, status, source_span }        // 承诺
Claim    { id, text, conditions, evidence[], counter[], confidence } // 观点卡片
Persona  { version, style_vec, value_order[], heuristics[], taboos[] }

Edge: (Fact)-[:EVIDENCE_OF]->(Claim)
      (Event)-[:PART_OF]->(Thread)
      (Fact)-[:CONTRADICTS]->(Fact)   // 显式建模矛盾，不做消解
      (Claim)-[:SUPERSEDES]->(Claim)  // 观点演化，保留版本链

两个设计决定值得单独说明。其一，矛盾显式保留。人的想法本就会变、会自相矛盾；系统消解矛盾等于抹掉了最有价值的信息——「我三个月的判断发生过反转」本身就是重要的自我认知。其二，观点带版本链。分身回答「我现在的看法」时，能同时给出「这个看法何时形成、之前是什么」，这才是决策密度的真正提升。

07交互设计

7.1 手表端：三个动作，不看屏幕

动作行为设计理由
单击复杂功能开启/结束一次采集会话，伴随触觉确认与常驻指示唯一主入口，抬腕即可，无需进入 App
双击打「重点」标记，写入 ±60 秒高优片段捕捉「这句话重要」的瞬时判断，是人工监督信号
长按表冠静默 30 分钟（红区），期间不采集且不积累任何缓冲提供物理化的隐私开关，比设置菜单里的开关更可信

表盘常驻一个 4pt 的点状标识表示正在采集；进入「红区」时标识变为空心。这是产品伦理的底线，不可为美观移除。

7.2 iPhone 端：每日 90 秒的确认仪式

采集是被动的，确认必须是主动的。日终推送一条「今日记忆」卡片，只做三件事：

3 条关键事实
→
1 条待确认观点
→
滑动：对 / 错 / 补充

这个动作同时完成两个目标：给用户控制感（不是被偷偷记录），给模型标注信号（低成本持续纠偏）。确认率是产品的第一北极星指标——它同时反映价值感与信任度。

7.3 输出形态

  • 周度复盘：本周说过的话里，有多少与上周判断不一致？哪些承诺未闭环？——这一条最能产生「原来我是这样的人」的震动。
  • 会前简报：基于历史交互生成「与这个人上次谈了什么、他关心什么、我答应过什么」。
  • 分身问答：「如果是你会怎么回这封邮件？」输出草稿 + 依据片段 + 与历史决定的相似度。

08隐私、合规与伦理红线

最高优先级风险

本产品采集的是他人的语音，属于处理第三方个人信息。在中国大陆运营须符合《个人信息保护法》关于告知同意的要求；在部分司法辖区（如加州、欧盟成员国）对对话录音有更严格的双方同意规则。这不是可以通过产品文案规避的风险，而是决定产品能否存在的约束。

风险具体表现设计要求（不可降级）
未告知录音同事、家人在不知情下被采集首次启动强制同意流；提供「一键向在场者说明」的标准化提示卡；企业场景须管理员先行获得组织授权
职场伦理被用于绩效、纠纷、取证用户协议明令禁止作为劳动争议证据使用；不提供音频导出与分享功能（仅本人可听）
数据安全音频泄露即不可撤销端到端加密，密钥仅存 Secure Enclave；云端仅存转写文本与加密音频，音频 30 天自动转冷/可配 7 天即删
敏感场景医疗、法律咨询、私密谈话内置场景识别（如检测到医院叫号、法律术语）自动暂停采集并提示；提供地理围栏红区
心理负担「被监视感」导致弃用所有采集有可见指示；提供「今日未记录时段清单」，把不可见变为可见；每周一次「数据体检」提醒可删
